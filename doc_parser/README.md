# doc_parser — 문서 읽기 컴포넌트

파일을 읽어 **제목 / 본문 / 표 블록**으로 바꿉니다. 블록마다 원래 위치(페이지·시트·슬라이드·줄)가 붙고,
표는 행·열 그대로 유지됩니다(숫자가 열 머리·단위와 떨어지지 않게). LLM·네트워크를 쓰지 않으므로 같은 파일은 항상 같은 결과.
검색용으로 자르는 일은 [`doc_chunker`](../doc_chunker/)가 합니다.

## 설치·사용

```bash
PY=python
$PY -m pip install --config-settings editable_mode=compat -e .    # 이 폴더에서 (설치 방식은 doc_reader README)

$PY -m doc_parser 보고서.pdf            # 제목·경고와 블록을 위치와 함께 출력
$PY -m doc_parser 보고서.pdf --json     # 블록을 JSON 한 줄씩
```

```python
from doc_parser import parse_file, register_parser

doc = parse_file("보고서.pdf")           # ParsedDoc(path, kind, title, blocks, sha256, warnings)
for b in doc.blocks:                     # Block(type="heading"|"text"|"table", loc, text, level, rows, image, bbox)
    print(b.loc.label(), b.render())     # "p.3", 마크다운 형태

register_parser(".hwpx", my_parser)      # 형식 추가: fn(path) -> (title, blocks, warnings)
```

## 화면·A2A

읽기 검수 화면과 A2A 창구는 [doc_reader](../README.md) 서버에 있습니다 (`python -m doc_reader serve` → `/read/`, 기능 `parse-document`).
이 패키지의 `service.py`(읽기 데스크: 작업 대기열·SQLite)를 그 서버가 씁니다. `a2a.py`는 도메인 코드 없는 A2A 1.0 배관으로,
doc_reader·doc_writer·meal_log가 import합니다 — 바꾸면 그쪽 테스트도 돌린다.
블록 `bbox`(PDF 포인트 `[x0, y0, x1, y1]`)는 원본 위에 블록 자리를 그리려고 추가 — 기존 필드는 그대로.

## 형식별 처리 (`doc_parser/<형식>.py`)

| 형식 | 모듈 | 처리 |
|---|---|---|
| txt·md | `text` | `#` 제목, `1.`/`1.1`, `[안건 1]`, `제3조 (…)`, 로마 숫자 제목. 파이프 표. cp949 자동 |
| docx | `word` | 제목 스타일·개요 수준으로 장·절, 병합 칸 중복 제거, 1×1 상자는 본문 |
| xlsx | `excel` | 시트마다 제목, 문장 줄과 표 구간 분리, 숫자는 셀 서식대로(천 단위·소수·%), 계산값 없는 수식은 수식 그대로 + 경고 |
| pptx | `powerpoint` | 슬라이드마다 제목, 글머리표 수준, 표, **차트는 데이터 표로**, 발표자 노트, 쪽 번호 제외 |
| pdf (글자 층) | `pdf` | 책갈피 또는 글자 크기로 제목, 반복 머리말·꼬리말 제거, 격자 표(검사 후 채택) / **세로선 없는 줄무늬 표는 글자 정렬로**, 여러 페이지 표 이어붙이기(페이지 끝에 남은 머리 행 포함), 줄바꿈 복원(하이픈 끊김은 붙임). 스캔 페이지는 경고 후 건너뜀 |

지원 안 함: hwp/hwpx, 구형 doc/xls/ppt → `UnsupportedFormat`. 스캔 PDF는 아래 OCR 옵션을 켰을 때만.

## OCR 옵션 (PDF의 스캔 페이지·이미지, 기본 꺼짐)

기본은 모델·네트워크를 쓰지 않는다. `--ocr-url`(또는 `parse_file(path, ocr=HttpOcr(url))`)을 주면:

- **글자층 없는 페이지** → 페이지 전체를 읽음(제목·본문·표, 모델의 읽기 순서). 스캔본뿐 아니라 **글자를 벡터 도형으로 그린 PDF**
  (디자인 도구·PDFKit 내보내기: 폰트 0개, 도형 수백 개 — 미리캔버스 샘플 15개 전부)도 포함. OCR 없이 읽으면 경고 후 건너뜀
- 머리말·꼬리말: 모델이 표시한 것도 글자층과 같은 규칙(쪽 절반·최소 3쪽에 반복)일 때만 지운다 — 모델은 한 쪽짜리 서식의
  맨 위 제목도 "머리말"로 분류함(캠페인 기획서). 쪽번호는 항상 지우고, 글자 없는 장식 머리말("× × × ×")도 지움
- **글자층 있는 페이지의 래스터 이미지**(페이지 면적 1% 이상, 글자층이 덮지 않은 것) → 그 영역만 잘라 읽어
  `[그림] Multi-Head Attention / Add & Norm …` 블록 하나로 원래 위치에 넣음. 본문은 글자층 그대로(중복 없음)
- 벡터로 그린 차트·도식은 대상 아님(글자는 이미 글자층에 있음)

누가 무엇을 읽나:

| 대상 | 읽는 것 | 이유 |
|---|---|---|
| 본문·제목·표 | PaddleOCR-VL-1.6 (레이아웃 + VLM) | 한국어 실측 비교에서 가장 정확 (TT Lab 2026-10-30, 인용) |
| 차트 | VLM이 숫자 표로 변환 + **PP-OCRv5가 제목·단위·범례를 `[차트] 분기별 매출액 (억원)`으로** | VLM 표 변환은 제목·단위를 버림 |
| 그림 속 라벨 | PP-OCRv5 (한국어 모델, 영문도 읽음) | VLM은 화살표 도식에서 반복 루프("Linear ↑ ↑" ×670). 줄 단위 인식은 구조적으로 반복 안 함 |

스캔 페이지 그림: 모델 상자가 그림 제목을 가로질러 자르면(트랜스포머 스캔본 p.4 "Scal|ed Dot-Product Attention") 상자 바깥에
잉크가 이어지는 동안 흰 틈(위아래 6pt, 좌우는 글자 높이 비례)이 나올 때까지 넓히고, 넓힌 영역을 다시 읽는다(경고 "넓혀 다시 읽음"). 서버의 그림 영역 읽기는
표가 없으면 영역 전체를 한 번에 줄 단위로 읽는다 — VLM이 그림을 조각으로 나누면 조각 밖 제목이 빠지고 두 조각에 걸친 제목이 두 번 나왔다.

그림 라벨에서 한 글자짜리이면서 주변 글자 높이 중앙값의 60% 미만인 것은 뺀다 — 상자 사이 화살표 머리를 "4"로 읽음(점수 0.965라
점수로는 못 거름, 높이 16px vs 글자 ~30px). Q·K·V 같은 한 글자 라벨은 높이가 같아 남는다.

안전장치(경고로 표시): 숫자가 절반 미만인 "차트" 표는 표로 쓰지 않음 / 그림 글자 인식 신뢰도 중앙값 0.7 미만이면
생략(회전 글자 등 — 정상 그림 0.996+, 회전 글자 0.40~0.48 실측) / 반복 생성은 잘라냄

```bash
bash tools/ocr.sh start      # vLLM :8091(글자 생성) + paddle :8090(레이아웃·프로토콜). 첫 실행은 모델 2GB 다운로드
$PY -m doc_parser 스캔본.pdf --ocr-url http://<WSL IP>:8090      # 주소는 start 출력 그대로
bash tools/ocr.sh stop
```

구성: `tools/ocr_server.py`는 별도 env(`~/miniconda3/envs/paddleocr`, paddlepaddle-gpu 3.4.0 cu129 + paddleocr 3.7.0)에서
돈다 — paddle 의존성이 doc_parser 쪽 env에 들어가지 않게. 글자 생성은 기존 `vllm` env가 맡는다.

WSL에서 겪은 것 (`tools/ocr.sh`에 반영):
- paddle 자체 디코더는 그림 1장에 12분 넘게 걸림(GPU 사용률 2~5%, CPU 1코어 90%) → 글자 생성은 vLLM으로
- paddle은 `LD_LIBRARY_PATH=/usr/lib/wsl/lib` 없으면 libcuda를 못 찾음
- vLLM은 nvcc가 없어 `--attention-backend TRITON_ATTN` 필요. `--enforce-eager`를 빼면(CUDA 그래프) 생성 93 → 675 tok/s
- 블록을 동시에 보내면 실행마다 결과가 미세하게 달라짐(170개 중 4개) → 한 번에 하나씩(시간 +30%)
- `--gpu-memory-utilization 0.35`만 주면 KV를 8.6GB 잡아둠 → `--kv-cache-memory-bytes 1GiB`
- 27B 서버(23.6GB)와 동시에 못 띄움

## 레이아웃 옵션 (그림 안 글자 분리, 기본 꺼짐)

글자층만으로는 그림 속 단어(축 라벨, 어텐션 맵 단어)와 본문을 구분할 수 없다. 그래서 단어 격자가 한 단어짜리 문단
수십 개나 가짜 "줄 맞춘 표"가 되고, 그 표가 **아래 캡션·본문까지 행으로 빨아들인다**(테스트 `test_layout_groups_figure_words`).
`--layout-url`(또는 `parse_file(path, layout=HttpOcr(url))`)을 주면 페이지마다 PP-DocLayoutV3로 그림·차트 영역만 받아:

- 그림 영역 안(줄 면적 60% 이상)의 글자층 줄 → `[그림] a / b / …` 블록 하나로 그림 위치에. 표 정렬 판정에서도 뺌
- 그림 영역 안의 괘선 표(find_tables) → 그림의 일부로 보고 버림(글자는 그림 블록으로)
- **그림 영역 밖 글자는 레이아웃 판정과 무관하게 그대로** — 레이아웃 모델 셋 모두 차트 위 짧은 문장을 캡션으로
  오분류했다(아래 비교). 글자를 버리지 않으므로 레이아웃이 틀려도 최악은 지금과 같은 결과
- 서버 실패 시 그 페이지는 경고 후 글자층만으로(옵션 없을 때와 동일)

서버는 OCR 옵션과 같은 `tools/ocr.sh start`(같은 주소). 둘을 함께 켜도 된다.

## 텍스트·그림 한꺼번에 뽑기 (`--extract-output DIR`, PDF)

```bash
$PY -m doc_parser 보고서.pdf --layout-url $URL --ocr-url $URL --extract-output out/보고서
```

| 파일 | 내용 |
|---|---|
| `DIR/<이름>.md` | 문서 순서대로 제목·본문·표, 그림 자리에 `![p.4 p004_fig1.png](images/p004_fig1.png)` + 그림 속 글자. 페이지 바뀌는 곳에 `<!-- p.N -->` |
| `DIR/images/p{쪽}_fig{n}.png` | 그림 하나당 한 장. PDF에서 직접 렌더링(긴 변 1000px 이상, 벡터 그림도 선명), 여백 4pt, 그림에 묶인 글자층 라벨까지 포함 |
| `DIR/blocks.jsonl` | 블록 JSON (`image` = images/ 안 파일 이름) |
| `DIR/meta.json` | 원본 경로·sha256·제목·블록/그림 수·경고 |

- 무엇이 그림으로 뽑히나: 래스터 이미지(면적 1%↑, 옵션 없이도) / 벡터 그림·차트(`--layout-url` 필요) / 스캔 페이지 속 그림
  (`--ocr-url`; OCR 없이 스캔 페이지면 페이지 통째로 한 장)

## 알려진 한계

- Word PDF는 숫자와 한글 사이에 공백이 들어감("제12 장") → 키워드 검색 쪽에서 정규화 필요
- 글머리표가 글자가 아니라 그림으로 그려진 PDF(Chromium 인쇄 등)는 항목이 한 문단으로 합쳐짐
  (`- `·`• `·`※ `처럼 글자로 쓴 글머리표는 2026-11-15부터 항목마다 나뉨 — 트랜스포머 논문 p.5 항목 3개 분리, 긴 문서 회귀 변화 없음)
- 여러 페이지에 걸친 표는 시작 페이지 위치만 남음 (행마다 페이지 번호 없음)
- 2단 편집 PDF의 읽기 순서는 시험하지 않음 (레이아웃 옵션도 아직 읽기 순서에는 쓰지 않음)
- 글자층만 쓰면 그림 속 단어가 한 단어 문단·가짜 표가 되고 아래 문단까지 표로 빨려듦 → 레이아웃 옵션으로 해결
- OCR: 단어를 격자로 늘어놓은 그림을 레이아웃이 "표"로 분류하면 그대로 표가 됨(트랜스포머 스캔본 p.15, 37행×18열).
  "차트"로 분류된 경우만 숫자 비율로 걸러낸다 — 진짜 표에도 글자 표가 많아 표는 거르지 않음
- 스캔 페이지 그림 상자를 넓히는 폭은 한 변에 72pt(또는 상자의 1/2)까지 — 모델 상자가 72pt 넘게 빗나가면 여전히 잘림.
  멈추는 흰 틈은 위아래 6pt, 좌우는 가장자리 글자 잉크 높이의 0.8배(6~16pt) — 그보다 넓게 띄운 제목은 첫 단어 앞에서 멈춤
  (시험: 12pt 제목 50pt 잘림 → 복구, 20pt 제목 단어 틈 7.8pt 넘어 복구·아래 본문으로 안 번짐)
- OCR(한국어 서식): 로고 글자("COMPANY LOGO", "MIRI.DIH")도 본문으로 들어옴, 머리말로 분류된 제목은 제목이 아니라 본문 블록,
  오인식 예: "캠페인" → "켐페인". 서식 대부분은 표 하나로 읽혀 블록 수가 적음(정상)
- OCR: 값 라벨 없는 차트의 숫자는 눈금으로 추정한 값(정확도 실측 안 함). 한국어 본문 문서·실제 스캔(기울기·얼룩)도 아직 실측 안 함
